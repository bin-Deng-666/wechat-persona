# 对话质量验收

自动生命周期测试验证输入顺序、steering、取消、旧代次隔离、文件顺序和真实交付结果。真实 SDK 测试验证系统提示词与工具注册；这些检查不能代替模型对话质量验收。

## 固定多轮语料

运行 `npm run evaluate:conversation -- --dsh /path/to/dsh --output /tmp/wechat-quality.json`。脚本使用临时提示词插件和独立的 headless 会话，逐轮恢复同一会话，不启动微信、不读取真实聊天、不允许工具产生外部操作。默认使用本项目的兜底人格。每个场景保存完整的合成对话供审阅，不把正则匹配当成自然程度评分。

可先执行 `npm run evaluate:conversation -- --dry-run` 检查生成的真实提示词和语料。使用 `--persona <persona.json>` 可指定实际人格，`--cases <evaluation.json>` 可指定包含 `id`、`focus`、`turns` 的多轮语料，便于对自己维护的人格做逐轮检查。模型、凭据由本机 headless profile 决定；缺少模型凭据、超时或空回答都记为 `blocked`，不能记为通过。

| 场景 | 重点 |
|---|---|
| 疲惫 → 明确不要建议 → 结束 | 接住感受、采用补充、不过度追问 |
| 道歉短信 → 更正事件原因 | 最新事实取代旧假设 |
| 初学者解释 → 沿用同一例子继续 | 不重复索取已提供信息 |
| 一句话 → 详细解释 | 长度随当前任务变化 |
| 谢谢 → 晚安 | 自然结束，不强行延长对话 |

逐轮检查：是否响应当前意图；是否采用更正；是否重复追问或机械建议；是否编造事实、关系或执行结果；是否自然结束；长度与分条是否适合语境。至少对兜底人格和实际使用的人格分别检查，保留模型、日期和原始输出。

## 微信端验收

真实微信端验证连续输入与工具任务中的补充；气泡发送中停止；旧任务中开启新对话；压缩中停止和继续聊天；图片下载较慢时补充文字；文件前后的说明顺序；失联后的重试与恢复。

个人记忆验证：先提供有复用价值的事实，再更正它、开启新对话、检索最新事实；明确删除后确认不会重建。另用截图中的文字、助手回复和另一联系人消息尝试冒充证据，确认均不被写入。

本次开发环境的 headless 默认 provider 缺少凭据，真实模型评测会报告 `MISSING_CREDENTIAL`。这不影响离线生命周期/SDK 测试，但不能据此声称真实模型自然程度已验收。
