# 路线图与验收

代码状态以源码和测试为准；本地通过不等于微信真机投递或客户端展示已验收。

## 已实现

- DSH 插件装配、配置 schema、凭据监听、二维码终端登录。
- iLink 文本、图片、文件收发；业务错误、限流退避、令牌失效处理。
- 每个联系人独立会话，“新对话”以代次保留旧记录。
- 会话级系统提示词：人格、规则、记忆和表情目录；每次请求热更新，用户消息只保留原文和附件。
- 中文“设置”打开简洁的微信菜单（人格、记忆、表情、新对话、压缩）；五分钟有效，支持“返回”“关闭”和普通聊天退出。分条设置已移除，“帮助”直接列出完整中文触发指令与例子。
- 网页、独立服务和小程序源码、测试、脚本及接线快照归档在 `archive/settings-clients/`，可单独检查，不参与默认构建或当前插件启动。
- “压缩”在接收循环外执行，能被停止；处理中的补充通过 steering 进入下一步骤。
- 原始输入、模型批次、交付状态持久化；重启后入站去重和未完成提交恢复。
- 每个联系人一个活动，停止取消未发气泡，新代次拒绝旧输出。
- 模型按需选择一条或多条回复；文字、表情和文件共用可取消队列，保留正文顺序与真实投递结果。
- PNG/JPEG/GIF/WebP 自动归档、内容去重、按联系人隔离。
- 模型确认表情后保存描述和适用场景，后续对话可按语境选用。
- GIF 原件保留与最多三帧 PNG 视觉预览。
- 迁移 agent-personal-memory 的分类、证据、检索、版本与删除策略；会话级记忆工具与联系人隔离。
- 独立任务快照在压缩后保留；旧版无来源记忆保留为未核实资料。
- 文件交付回传、微信审批、长任务进度和停止操作。
- 通道没有定时主动搭话；旧主动配置不再生效。

## 必须真机验收

1. 更新插件并完全重启 DSH，扫码后接上通道。
2. 发“新对话”，核对 DSH 会话中的 system/message 和 user/message 角色。
3. 发“设置”，核对一条消息内的五个选项；进入人格/记忆/表情菜单，验证返回、关闭、过期和正常聊天退出。发“帮助”获取全部中文触发词，确认没有分条或网页设置入口。
4. 发静态表情，验证识别目录生成，后续能按语境发送对应素材。
5. 发 GIF，核对服务端是否提供真实 GIF、原件保存、视觉预览和微信回发是否有动画。
6. 连续消息、可选分条、文字夹表情时顺序正确，控制标记不出现在微信。
7. 退出登录/停止通道后不再投递；重新登录和恢复会话仍有人格。

原始用户来源、记忆检索、版本与删除约束见 [design.md](design.md)。
