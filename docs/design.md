# 设计

目标是微信里的单聊联系人：用户原文与系统规则分开，回复可按语境一条或多条，能理解媒体并复用已确认的表情，不定时主动打招呼。

## 分层

```text
微信 ⇄ iLink
       │
       ▼
channel/runtime.ts       准入、去重、中文指令、消息合并、事件路由
       │ 原文与附件
       ▼
bridge/session.ts        peer + generation ⇄ DSH 持久化会话
       │ followup(user message)
       ▼
DSH agent                模型、工具、权限、会话历史
       ▲ system-prompt/assemble（当前 agent 作用域）
bridge/prompt.ts          读取人格/设置/记忆/表情目录 → system section
       │
       ▼ assistant/message
表情识别与记忆落盘 → ReplyQueue → 文字/表情依序发送
```

- `ilink/` 不依赖宿主，负责请求、协议错误、媒体 AES 与上传下载。
- `persona/` 负责人格数据、聊天设置和表情素材目录。
- `bridge/` 接入 DSH 会话、提示词、媒体、审批和回复队列。
- `channel/` 处理微信入口、中文指令、设置卡片与轮询。
- `index.ts` 只组装依赖与管理账号、通道和注册生命周期。

## 对话消息与系统提示词

`Channel.flush()` 只调用 `createUserMessage()` 组装用户原文与图片/文件附件。纯图片成功处理时没有额外的“对方发了图片”用户文字。媒体下载、能力探测或解码失败时保留原文，并提供简短降级说明。

`PeerSystemPrompt` 在当前 agent 作用域注册 `system-prompt/assemble` 监听器，每个模型步骤异步读取当前设置、人格、记忆和素材目录，在宿主组装结果中添加 `wechat-persona:persona` section，保留工具和运行时规则。已渲染的文本使用 `interpolate: false`，防止人格或记忆中的字面花括号被宿主再次插值。

系统提示词的持久化、system/message 的新增/替换、不同模型的 system 更新能力由 DSH 负责。插件不手写会话日志、不修改模型请求对象、不把人设伪装成 user 消息。

新建和恢复的会话在 unpublished setup 中安装；借用 GUI 已启动的会话在取得句柄时安装。注册对同一 agent 幂等；通道卸载撤销自己的监听器。作用域继承允许父监听器看见子 agent，所以监听器还检查精确 agent 身份，防止微信人格进入子 agent。

人格和记忆每次组装重读，没有“首轮/暖过”状态机。旧版本已经写入用户历史的人设不自动改写，升级后可发“新对话”从干净历史开始。

## 表情素材

`StickerLibrary` 同时管理原件与按联系人隔离的目录：

```text
stickers/shared/<名字>.<ext>                  人工共享表情
stickers/assets/<hash前2位>/<完整hash>.<ext>   原件，按内容去重
stickers/chats/<联系人hash>/index.json        识别状态、名字、描述、场景、时间、最新ID
```

收到的图片先保存为 pending。模型只有实际看清且确认可复用表情后，才能输出 `[收录表情:ID|名字|描述|适用场景]`；普通截图、照片、证件等用 `[忽略图片:ID]` 排除。未知 ID 和不属于这个联系人的素材不能被标注或发回。用户可以用“表情 收 名字”明确收藏最近一张。

原件共享内容存储，识别目录与可用权限不跨联系人共享。同一联系人的目录更新串行化并原子替换。原有根目录图片和 shared/ 图片为人工导入素材。

GIF 原件独立保存。视觉输入生成最多三张 PNG 预览，合成透明度与 disposal；限制画布、帧数和总解码量。回发仍读取原始 GIF 字节。微信客户端是否保留动画和是否以原生表情方式显示，需要真机验收。

## 回复与指令

中文“菜单/设置/帮助/新对话/状态/人格/分条/停止/表情”为主要入口。精确匹配整条消息及参数格式，不在普通聊天中搜索关键词。旧斜杠指令仍可用。菜单选项只在 5 分钟有效期内消费单个数字。

最终回答先解析记忆和素材识别标记、持久化结果，再进入按联系人串行的回复队列。`[分条]` 表示模型明确选择的消息边界，没有标记的短回答默认一条。超长内容根据发送形态和传输上限切分。每个气泡最多发送一个表情，文字与表情共用队列、节流和重试。

没有主动搭话定时器。进度提示、审批请求和任务失败说明只反馈用户已经发起的工作。

## 会话与生命周期

- 同一 peer、同一 generation 对应同一会话 ID；“新对话”递增 generation 并保留旧记录。
- 会话创建时写入 cwd；恢复时保留原有 header。
- `PeerSessions` 优先复用 live 句柄、借用 registry 中的会话，然后 resume/create。
- 自己创建的 agent 在通道停止时释放；借用会话不由本插件销毁。
- 停止时撤销事件订阅、清除待合并消息和进度定时器，等待识别与出站队列完成，再撤销提示词贡献。

## 收发约束

1. 只接受白名单 peer；陌生人不建会话、不执行指令、不回复。
2. 最终投递源是 durable `assistant/message`；带工具调用的旁白不发。
3. 每次回复带对应入站消息的 context_token；排队时捕获令牌，避免后来的消息覆盖。
4. HTTP 200 仍要验证业务回执；ret:-2 按 2/4/8/16 秒退避。
5. 轮询游标定期落盘；消息 ID 在本次运行内去重。最后一次落盘后的短窗口仍可能在异常退出后重放。
6. 模型/媒体/发送失败有说明，不把整条消息静默丢掉。

## 当前边界

群聊、出站原生定位/按钮/语音、记忆自动摘要、上下文用量展示和逐联系人成本统计不在当前实现内。媒体和模型请求的本地路径可以测试，真实协议投递与客户端展示仍需真机验收。
